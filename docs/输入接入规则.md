# 节点输入接入规则

生成类节点的「能接什么素材」「哪些模式能点」的完整约定。所有判定都来自四张规则表 + 一个仲裁函数，**同一份表同时驱动标签可点性和连线拦截**，不存在两处各写一遍的情况。

- 规则表：`js/infcanvas-flow.js` 第 384–457 行
- 仲裁函数：`modeReasonFor(mode, counts, table, denyText)`，第 540 行
- 连线门：`audioWireReason` / `imageWireReason` / `textWireReason` → `genWireReason` → `isValidConnection` + `onConnect`，第 4426–4496 行
- 断线回收：`reconcileModes()`，第 4711 行

## 一、总览矩阵

「媒体」指图片 / 视频 / 音频三类素材节点；**文本节点不是素材，是提示词**，它永远能接，不参与任何数量限制。

| 节点 | 模式 | 图片 | 视频 | 音频 | 文本 |
|---|---|---|---|---|---|
| 视频 | 参考生视频 | ≥0 | ≥0 | ≥0 | 可接 |
| 视频 | 文生视频 | — | — | — | 可接 |
| 视频 | 图生视频 | 1 | — | — | 可接 |
| 视频 | 首尾帧视频 | 2 | — | — | 可接 |
| 图片 | 文生图 | — | — | — | 可接 |
| 图片 | 图像编辑 | ≥1，不限 | — | — | 可接 |
| 图片 | 图像放大 | 1 | — | — | 可接 |
| 图片 | 背景移除 | 1 | — | — | 可接 |
| 音频 | 文生音乐 | — | — | — | 可接 |
| 音频 | 音乐翻唱 | — | — | 1 | 可接 |
| 音频 | 语音合成 | — | — | — | 可接 |
| 音频 | 语音克隆 | — | — | 1 | 可接 |
| 文本 | 智能对话 | ≤50 | ≤100 | ≤100 | 可接 |
| 文本 | 语音转录 | — | — | 1 | 可接 |

「—」= 该模式**完全不能有**这类素材，接了就连线被拒或标签变灰，没有例外。
「1」= 恰好 1 个，0 个时标签不可点，2 个时连线被拒。
「≤N」= 上限 N 个，超出时连线被拒。文本智能对话的 50 / 100 / 100 不是拍脑袋的数字，而是 `TextGenerateV2` 的 autogrow 模板本身的上限（`image1..50`、`video1..100`、`audio1..100`），超出节点根本声明不出对应的输入。
全能参考另有整体下限 `_minMedia:1`：图片/视频/音频加起来至少 1 个，纯文本不算。

## 二、连线门（节点级，与当前模式无关）

模式只管「标签能不能点」，连线门管「线能不能接进来」。两层都过才算合法。

| 目标节点 | 接受的来源 | 拒绝时提示 |
|---|---|---|
| 视频 | 图片 / 视频 / 音频 / 文本，数量不限 | 无（节点级不拦，全部交给模式判定） |
| 图片 | 图片 / 文本 | `图片生成节点不能接入视频素材` / `图片生成节点不能接入音频素材` |
| 音频 | 音频 / 文本 | `音频生成节点只能接入音频或文本素材`；第 2 段音频 → `音频只能接入 1 个，请先断开已连接的音频` |
| 文本 | 图片 / 视频 / 音频 / 文本 | 图片第 51 张、视频第 101 个、音频第 101 段 → `「LLM」最多接入 N 张图片 / 个视频 / 段音频` |

文本节点**不再有两族互斥**。`TextGenerateV2` 本身就把图片、视频、音频塞进同一次 `clip.tokenize()` 调用，所以混接是合法的；按种类设上限就够，跨界不再拒绝。

- 图片 ≤ 50、视频 ≤ 100、音频 ≤ 100，逐种类独立计数（`TEXT_WIRE_CAPS` 直接从 `TEXT_INPUT_RULES.LLM` 派生，两处不会打架）
- 文本线：任何模式、任何数量都放行，不影响模式判定
- 接了图片/视频之后，语音转录会变灰（它只收「恰好 1 段音频、其它都不许」），此时模式自动迁到 LLM，而不是把线丢掉

拒绝时弹 `无法接入` toast，文案就是上表原因。Vue Flow 对非法连接本身完全静默，不弹提示会被当成「拖不动」。

## 三、模式标签的可点性

- 不可用的标签：`opacity:.5`、`cursor:not-allowed`、hover 不变色，`title` 直接显示原因（如「图片放大」最多接入 1 张图片）。
- 点击不可用的标签：弹 `该模式不可选` + 原因，当前模式保持不变。

原因文案由 `modeReasonFor` 统一生成，共四种句式：

| 场景 | 文案 |
|---|---|
| 接入了该模式不收的种类 | `「图片生成」为纯提示词模式，不接入媒体素材` / `「图片放大」只能接入图片` |
| 整体媒体数量不足 | `「全能参考」需要至少接入 1 个图片/视频/音频素材，当前 0 个` |
| 低于下限 | `「图片放大」需要 1 张图片，当前只有 0 张` |
| 超出上限 | `「图片放大」最多接入 1 张图片` |

量词按种类走：图片「张」、视频「个」、音频「段」。

## 四、接上 / 剪断时的模式自动迁移

线是主人，模式跟着线走。**绝不因为模式不合适就丢掉用户刚画的线。**

| 节点 | 触发 | 结果 |
|---|---|---|
| 图片 | 新线让当前模式失效 | 能进「图片编辑」就进（≥1 张图），否则回「图片生成」 |
| 图片 | 剪断后当前模式失效 | 第一个可用模式（通常回到「图片生成」） |
| 音频 | 接入音频时当前是纯提示词模式 | 切到同族的参考模式：音乐设计 → 音乐翻唱，语音设计 → 语音克隆 |
| 音频 | 剪断音频 | 同族退回：音乐翻唱 → 音乐设计，语音克隆 → 语音设计 |
| 文本 | 接入音频（且当前没有图片/视频） | 语音转录 |
| 文本 | 接入图片或视频 | LLM |
| 文本 | 已有图片/视频，再接入音频 | 保持 LLM（混合合法，不再拒绝） |
| 文本 | 剪断后当前模式失效 | 第一个可用模式 |
| 视频 | 新线让当前模式失效 | 切到「全能参考」（唯一能吃任意素材的模式） |

迁移时弹 `已切换到 XXX` + `当前素材不符合「旧模式」，连线已保留`。

断线回收由 `reconcileModes()` 负责，`watch(state.edges, flush:'post')` 触发，**只修已经失效的当前模式**，可用的一律不动。它直接写 `node.data[field]`（并同步 Vue Flow 的 live 节点），**不走 `updateNodeData`、不 markDirty** —— 否则刚打开的画布会被标脏并自动保存。

## 五、素材槽（缩略图行）

线接进来之后，节点上要能看见接的是什么。槽位表按节点分派，`null` = 跟着实际连线走，`[]` = 该模式整行消失（不留空槽）。

| 节点 | 槽位表 | 内容 |
|---|---|---|
| 视频 | `MODE_ASSET_SLOTS` | 参考生视频 `null`；文生视频 `[]`；图生视频 1 图；首尾帧视频 2 图 |
| 图片 | `IMAGE_MODE_ASSET_SLOTS` | 文生图 `[]`；图像编辑 `null`；图像放大 / 背景移除 各 1 图 |
| 音频 | `AUDIO_MODE_ASSET_SLOTS` | 文生音乐 / 语音合成 `[]`；音乐翻唱 / 语音克隆 各 1 音频 |
| 文本 | `TEXT_MODE_ASSET_SLOTS` | 智能对话 `null`；语音转录 1 音频 |

固定槽位的意义是：空节点也能看出「当前模式在等什么素材」，空槽提示为「图片槽（连接对应素材节点）」。悬停槽位浮出 160px 预览卡，图片直显、视频抽帧后自动播放、音频显示名称与时长。

## 六、文本节点的两个特殊约定

1. **文本节点接上线不会变成素材节点。** `isGenText` 只看自身内容（`asset` / `result` / 手输文字），不看 `hasIncoming`。否则 LLM 接了图之后就没了参数栏、也点不了运行 —— 而它存在的意义就是消费图片/视频/音频。
2. **文本线只写进第一个输入区。** 音频节点的「提示词 / 语气」是第一区，「歌词 / 朗读文本」是第二区，接进来的文本节点只会落在第一区（`applyNodeInputs(target, data, areaA)` 的第三参），永远不会污染歌词。

## 七、已知限制

- **多素材目前只有第一个进工作流。** 规则层已经放开（图片编辑不限张数、LLM 可接 50 图 / 100 视频 / 100 音频），槽位也会如实显示 图片1 / 视频2，但运行端 `buildPrompt` 只做两件事：把 `values.image/video/audio` 塞进同名 `{{占位符}}`，以及在节点 id 恰为 `3/4/5` 的老式文生图模板里插一个 `LoadImage + VAEEncode`。而 `api/` 下现有 5 个模板**一个 `{{…}}` 占位符都没有**，`TextGenerateV2` 的 `image1..50` 也不会被填充。也就是说：接多个素材在 UI 与规则层是通的，真正喂进工作流需要另做一层「按 autogrow 键名注入 `LoadImage/LoadVideo/LoadAudio` 并连到文本节点」。@ 引用（`@图片1`）同样只是提示词里的叙述标记，不会被剥离或映射到具体输入。
- **视频节点剪线不回收模式。** `reconcileModes` 只覆盖图片 / 音频 / 文本三类；视频剪到 0 素材后如果停在「全能参考」，标签会变灰但仍处于选中态。补上只是把这个 kind 加进循环。
